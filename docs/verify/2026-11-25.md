## Lavoro svolto

### Cycle C — SSH client version string (completato)
Dopo l'handshake il decoy SSH legge l'attributo pubblico
`paramiko.Transport.remote_version` ed emette un evento `connection.identified`
con `observed.network.ssh.client_version`.

- Input controllato dall'attaccante → limitato a 255 byte (RFC 4253 §4.2),
  troncamento **dichiarato** sotto `sensor_capture` (mai perdita silenziosa).
- Registrato **solo** come evidenza `observed`: mai identità dell'attaccante,
  mai claim di fingerprint derivato. Classi di provenienza mantenute distinte.
- Nuovo blocco `ssh` in `make_network_evidence`/`validate_network_evidence`
  simmetrico a `http`/`tls`/`dns` (sede naturale di una futura HASSH, differita).
- Le offer-list KEX/cipher (HASSH), JA4H/JA4 e il PCAP a container dedicato
  restano differite/bloccate (API privata paramiko / licenza / sidecar
  privilegiato) — **ADR 0005**.

### Cycle I — estrazioni incrementali dal monolite (ADR 0003)
Tre domini escono da `store.py` mantenendo invariata l'API pubblica:

1. **Relationship queries** → funzione pura `build_relation_graph(...)` in
   `store_relations.py`, priva di accoppiamento a SQLite; `Store.relations`
   delega.
2. **Case storage** → `CaseStoreMixin` in `store_cases.py` (CRUD casi, evidenze,
   note, history log, report e timeline); `Store` lo compone. Il mixin usa, via
   `self`, solo `connect`/`max_cases`/`_ioc_resolver`/`prune_cases` del backend
   composto.
3. **Analytics storage** → `AnalyticsStoreMixin` in `store_analytics.py`
   (geo_attacks, evidence_loss_summary, filter_options, dashboard e gli helper
   di filtro/ricerca client-side). Il vocabolario condiviso (`EVENT_FILTERS`)
   passa nel modulo leaf senza dipendenze `store_common.py`, evitando cicli di
   import tra `Store` e i mixin.
4. **Event storage** → `EventStoreMixin` in `store_events.py` (get_event,
   `_sql_filters`, page/list events, behavioral/detection context).
5. **Session storage** → `SessionStoreMixin` in `store_sessions.py`
   (page/list sessions, `_session_summary`, get_session bundle).

Lo split storage del Cycle I è così completo (6 domini in moduli `store_*`); il
dominio alert vive già in `alerts.py` e non era nel monolite. `Store` mantiene
il core di scrittura/ingest e resta il backend di riferimento composto.

- `store.py`: da ~2400 a **~938 righe** (−~1460 nella giornata).
- `store_relations.py`, `network_evidence.py` e `store_common.py` aggiunti al
  gate mypy; corretto un pattern di narrowing preesistente in
  `suricata_flow_evidence`.
- Comportamento invariato garantito da contract test, test case-workflow,
  dashboard e correlation-workspace.

#### Split route API per dominio (pilota)
Avviato lo split di `app.py` con il pattern **blueprint-factory**: una
`make_<dominio>_blueprint(...)` a livello di modulo cattura le dipendenze e
restituisce un `Blueprint` Flask con gli stessi URL assoluti. Gli hook
`before_request` (trust boundary) e `after_request` (security headers) a livello
app continuano ad applicarsi anche alle rotte del blueprint. Primo dominio
estratto: `api_detections.py` (`/api/v1/detections/config|coverage|stats`),
read-only e senza auth operatore. URL e comportamento invariati (test detection
verdi). Secondo dominio estratto: `api_status.py` (status di enrichment,
benign-scanner e threat-context) — anch'esso read-only, senza segreti né
richieste di rete. Terzo dominio estratto: `api_ips.py` (`/api/v1/ips/<ip>` e
`/api/v1/ips/<ip>/threat-intelligence`) — read-only su `store`, IP validato con
`ipaddress`, GeoIP/ASN resta enrichment mai identità. I domini restanti
seguiranno in modo incrementale.

## Invarianti verificati

- **Mai esecuzione** dell'input dell'attaccante: la client version è solo letta
  e registrata; `executes_attacker_input` resta `False`.
- **Separazione delle classi di evidenza**: la version string è `observed`;
  ASN/country restano `enrichment`; nessuna collassata in identità.
- **Perdita di evidenza dichiarata**: troncamento della banner esposto in
  `sensor_capture`.
- **Bounding dell'input ostile**: 255 byte sulla banner, cap sui nodi del grafo
  invariato.
- **API pubblica invariata**: contract test e test relazioni verdi dopo
  l'estrazione.
