## Verifica approfondita delle invarianti — log di audit operatore (PR #41)

- **Fail-closed (auth).** `GET /api/v1/audit` è coperto dall'hook globale
  `before_request protect_trust_boundaries`: ogni `/api/v1/*` (eccetto ingest
  sensori e `/api/v1/operator/status`) richiede `operator_authorized()`,
  altrimenti 401. Nessun "allow by default"; l'endpoint non reintroduce un
  percorso non autenticato. Verificato anche che la rete-sensore non può
  raggiungere endpoint operatore (403 `sensor_network_denied`).
- **Input ostile bounded.** `operator_audit.record()` tratta i valori
  operator-supplied come non fidati: strip dei caratteri di controllo e bound
  su operator (64), action (vocabolario stretto `ACTION_PATTERN`,
  `OperatorAuditError` su azione sconosciuta), target_type (64), target_id
  (128), outcome (whitelist), detail (max 32 chiavi, 256 char/valore,
  32 item/lista, 4000 byte serializzati → `{"truncated": true}`). Verificato a
  runtime con input contenente `\x00/\x01/\x02` e valori oversize: ripuliti e
  troncati correttamente.
- **Append-only / anti-tampering.** Migrazione v7 crea `operator_audit_log` con
  trigger `BEFORE UPDATE` che fa `RAISE(ABORT, 'operator_audit_log is
  append-only')`; verificato a runtime che un `UPDATE` out-of-band viene
  rifiutato (`IntegrityError`). `id` AUTOINCREMENT monotòno → una delezione
  out-of-band lascia un gap visibile.
- **Perdita di evidenza esplicita.** La retention (oldest-first, default 365g /
  1M righe, configurabile via `AEGIS_AUDIT_LOG_RETENTION_DAYS`/`_MAX_ROWS`)
  registra ogni prune come entry `audit.retention_prune` — mai silenziosa — e
  l'entry di prune è esente dal prune per età per non auto-cancellarsi.
- **Modello evidence-first.** Il nuovo materiale è metadato di sistema
  (attribuzione operatore), **non** un blocco `observed/enrichment/derived/
  hypotheses`: nessun campo è stato aggiunto a quelle classi e nessun dato
  derivato/ipotesi è finito in `observed`. L'audit non copia payload catturati
  né corpi di note operatore (solo attribuzione + metadati strutturati piccoli).
- **Nessun eval/exec/deserializzazione di payload.** Il detail è
  `json.dumps`/`json.loads` di sole strutture bounded prodotte dal server;
  nessun input dell'attaccante vi transita.
- **Robustezza del logging.** `record_audit()` racchiude la scrittura in
  `try/except` e logga l'eccezione: un fallimento di audit non trasforma
  un'azione già riuscita in un 5xx (l'azione è già avvenuta: nasconderla con un
  errore sarebbe peggio).
- **XSS/frontend.** PR backend-only: nessuna vista frontend aggiunta per
  l'audit, quindi nessuna nuova superficie di XSS stored nella dashboard SOC.
  `tests/test_frontend_safety.py` resta verde.
- **SQLite.** Connessione dell'audit log con le PRAGMA della convenzione (WAL,
  `foreign_keys=ON`, `trusted_schema=OFF`, `busy_timeout`). Migrazione v7
  idempotente (`CREATE ... IF NOT EXISTS`, trigger `IF NOT EXISTS`); DB vuoto →
  `user_version=7` senza errori; v7 incluso nei test di migrazione.
- **Privacy/GDPR.** Trail di sola attribuzione: registra *chi ha fatto cosa su
  quale entità*, mai corpi di note o payload. Il `source_ip` è l'IP della
  richiesta dell'operatore (non PII dell'attaccante) ed è normalizzato via
  `ipaddress.ip_address`. Retention dedicata e configurabile. `PRIVACY.md`,
  `AUDIT_LOG.md`, `OPERATIONS.md`, `THREAT_MODEL.md` e `.env.example`
  aggiornati nello stesso commit — docs allineate.
- **Docker.** Hardening invariato e intatto: `USER aegis` (non-root),
  `read_only: true`, `cap_drop: ["ALL"]`, `no-new-privileges:true`; nessuna
  porta di gestione esposta.
